- (decision) AD-1 [ADOPTED] Static-export, no server runtime. Binds all tools. Prevents: a tool adding route handler/server action that breaks next build export. Rule: all compute client-side; any network call goes to an external endpoint via fetch.
- (decision) AD-2 Tool catalog is single source of truth. Pure metadata registry src/lib/tools/registry.ts (no React). Routes, /tools index, sitemap, cross-promo ALL derive from it. Prevents: orphan tools missing from sitemap/index, divergent registration. Rule: adding a tool never edits routing/sitemap by hand.
- (decision) AD-3 [pattern ADOPTED from industries/[slug]] One dynamic route /tools/[slug] renders every tool via generateStaticParams from registry + generateMetadata for SEO, wrapped by shared ToolShell (SEO landing structure, result frame, lead slot, cross-promo). Prevents: each tool hand-rolling its own page/SEO/layout.
- (decision) AD-4 Tool = pure compute separated from UI. Each tool folder exports compute() (pure deterministic TS, unit-testable) + a client Tool component + zod input schema. Prevents: business math tangled in components, untestable, inconsistent. Rule: no calculation logic inside React components.
- (decision) AD-5 Tool input state is URL-owned. Inputs serialize to query params; shareable URL is the source of truth; result recomputes from inputs. Prevents: divergent share/deep-link/state handling per tool. Fits static export (client reads query).
- (decision) AD-6 Region-variable data in versioned date-stamped tables. bigha/biswa/marla per-state, RJ stamp-duty rates as data with asOf date + source URL, surfaced in UI. Prevents: scattered magic numbers, wrong regional answers, stale rates. Rule: no rate/factor hardcoded in compute; all from data module.
- (decision) AD-7 Single shared lead-capture. One <LeadSlot toolSlug> component + one client submit contract (common payload -> one configurable endpoint), feature-flagged OFF in Phase 1. Prevents: each tool inventing its own form/payload; inconsistent CRM data. Endpoint choice deferred (Phase 2).
- (decision) AD-8 Reuse existing design system. Tools use cream/navy/gold/ink/line tokens + font-heading/eyebrow utilities, plus a shared tool-surface component family (InputField, Slider synced w/ numeric, ResultCard, Chart). Prevents: N tools = N visual languages.
- (constraint) Indian number formatting: en-IN locale, rupee, lakh/crore grouping for money outputs. Shared formatter util. Prevents inconsistent number display across tools.
- (decision) Reviewer gap fix (AD-5): shared useToolState(schema) helper owns parse/serialize/defaults; tools never touch searchParams directly.
- (decision) Reviewer gap fix (AD-7): lead payload shape fixed {toolSlug,name,phone,email?,resultSummary,capturedAt} so CRM ingest is one schema.
